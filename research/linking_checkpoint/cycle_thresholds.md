# Stronger linking bounds from winding cycles

## Result and scope

The existing Type 7 `ray_4` obstruction extends from
`y^2 >= 35/4` to **`y^2 >= 63/16`**. The new ingredient is an
eight-edge cycle with period `(-3,4)`, rather than a three-edge cycle
with vertical winding one. The geometric diameter argument is unchanged.

This excludes one marking on a larger interval. It does **not** settle
Type 7 universality, nor does it exclude a full marking for Type 4 or 5.
The Type 7 conclusion inherits the strict-support/mixed-side and necessary
orientation-reduction premises of
[the final-polynomial proof](../type7_focus/final_polynomial.md).
The cycle inequalities themselves need none of the orientation enumeration.

## Geometric proof

Let an embedded flat torus have lattice generated by `h=(1,0)` and
`g=(1/2,y)`. Suppose the self-linking `q(h)` of parallel horizontal
geodesics is nonzero. As proved in [the diameter theorem](README.md#1-linked-parallel-geodesics-bound-the-diameter),
every pair of these geodesics has intersecting convex hulls. Each is a
simple closed curve of length one and therefore has diameter strictly
less than one half. The distance between any two surface points is
strictly less than one, and compactness gives `diam(T)<1`.

For any closed edge cycle with `k` edges and period `(m,n)`, its intrinsic
length equals the sum of its straight spatial edge lengths. Consequently

    sqrt((m+n/2)^2+n^2*y^2) <= length(cycle) < k.

If `n != 0`, this implies

    y^2 < (k^2-(m+n/2)^2)/n^2.

Thus at or above the displayed bound the horizontal slope is unlinked.
The strict inequality includes the threshold itself in the excluded range.

## Exact certificates for all seven sharp markings

The integer periods below are obtained directly from the checked-in edge
cocycles; vertex labels are those of `cases.json`.

| Marking | Cycle, with last vertex joined to first | Period `(m,n)` | `q(h)=0` whenever |
|---|---|---|---|
| Type 4, ray 1 | `1,3,6,4,5` | `(1,-2)` | `y^2 >= 25/4` |
| Type 4, ray 2 | `2,4,3,5` | `(1,-2)` | `y^2 >= 4` |
| Type 5, ray 1 | `0,2,3,1,5` | `(-1,2)` | `y^2 >= 25/4` |
| Type 7, ray 1 | `0,3,6,1,4,7,2,5` | `(-4,3)` | `y^2 >= 77/12` |
| Type 7, ray 2 | `0,3,6,1,4,7,2,5` | `(-1,3)` | `y^2 >= 85/12` |
| Type 7, ray 3 | `0,2,4,6` | `(1,-2)` | `y^2 >= 4` |
| Type 7, ray 4 | `0,1,2,3,4,5,6,7` | `(-3,4)` | `y^2 >= 63/16` |

These are the best bounds from this particular edge-cycle/diameter test,
as verified by exact enumeration of all simple cycles. They are not
claimed to be optimal geometric thresholds. In particular the separate
three-fiber convex-hull argument can give a different bound.

Arbitrary repeated-vertex closed walks cannot improve this test: split a
walk into simple cycles (and possible two-edge backtracks). Its period
divided by its edge count is a convex combination of the corresponding
cycle averages. The Euclidean norm of this average is at most the largest
norm of an individual cycle average. Hence a violated diameter test for
a closed walk already occurs for a simple cycle at the same modulus.

## Type 7 ray 4

The two cycles `0,2,4,6` and `1,3,5,7` both have period `(1,0)` in this
marking. The existing exact six-relation final-polynomial proof shows that
they must be linked in an embedded flat Type 7 realization, under its
stated geometric premises. On the other hand, the Hamiltonian cycle has
physical period `(-1,4y)`. If the two short cycles were linked, the
diameter theorem would give

    sqrt(1+16*y^2) < 8,

or `y^2 < 63/16`. This proves the improved exclusion, including equality.
It uses no limiting cap argument and no nonlinear solver result.

## Reproduction

From the repository root:

```sh
python3 research/linking_checkpoint/verify_cycle_thresholds.py
node research/type7_focus/verify_final_polynomial.cjs
```

The first checker uses only integers and `fractions.Fraction`, and reads
the actual archived cocycles. The second checks the inherited algebraic
certificate and its coverage of all sixteen archived sign models. Boolean
completeness is separately replayed by
`research/linking_checkpoint/verify_full_ring4.py` and the existing RUP
workflow. Neither script formalizes the topological diameter argument.
